# 小蛙回家路：后续路线图与待办

最后更新：2026-08-24  
适用基线：H5 正式开发版 + `iOSAppStore` 分支的离线 iOS 封装工程

本文档用于留存尚未完成的工作、验收标准和已经确定的产品决策。完成事项后勾选对应复选框，并在文末更新日期。

## 优先级

- **P0**：公开测试或 App Store 提审前必须完成。
- **P1**：用于验证留存和 IAA 变现，P0 稳定后推进。
- **P2**：正式发布资料和发布流程。
- **可选**：数据证明有必要后再做，避免过早堆功能。

## 推荐执行顺序

1. 真机稳定性测试。
2. 补足 iOS 原生体验和 App 化能力。
3. 接入真实广告与隐私合规。
4. 接入数据统计并验证核心指标。
5. 根据数据选择轻量留存功能。
6. 准备商店素材，完成 TestFlight 和审核。

## P0：真机体验与稳定性

- [ ] 在至少一台小屏 iPhone 和一台大屏/灵动岛 iPhone 上完整试玩。
  - 验收：安全区无遮挡，首页、HUD、教程和结算页无裁切。
- [ ] 连续游玩 20～30 分钟，观察帧率、发热、内存和音画同步。
  - 验收：无明显持续掉帧、白屏、卡死或声音叠加。
- [ ] 真机测试来电、锁屏、切后台、切回前台和音频中断。
  - 验收：恢复后不会自动蓄力、误跳、音效重复或进度异常。
  - 当前进度：H5 已实现失焦/切后台冻结和恢复保护，并通过自动化计时测试；仍需真机覆盖系统中断场景。
- [ ] 测试首次安装、覆盖安装、重新安装和旧存档迁移。
  - 验收：最高纪录和永久资源符合预期，旧数据不会造成崩溃。
- [ ] 测试飞行模式、断网和弱网。
  - 验收：离线游戏可正常启动；广告失败时有安全降级。
- [ ] 检查不同语言下的长文案和按钮布局。
  - 验收：简中、繁中、英语、日语、韩语均无溢出或截断。

## P0：iOS 原生体验与审核风险

- [ ] 复核现有原生触感反馈在真机上的强度和触发时机。
- [ ] 正确处理 iOS 音频会话、静音模式和系统中断。
- [ ] 增加原生成绩分享入口和分享失败兜底。
- [ ] 评估并接入 Game Center 排行榜。
  - 验收：未登录 Game Center 时游戏仍可正常游玩。
- [ ] 完善启动页、加载失败提示和 WebView 异常恢复。
- [ ] 提审前以 App Review Guidelines 4.2 检查娱乐价值和 App 化程度。
  - 说明：当前继续以离线 H5 + 原生 iOS 封装为基线，不因审核担忧直接迁移 Cocos。

## P0：IAA 广告与隐私

- [ ] 确定首发广告平台及支持地区。
- [ ] 在现有“消耗 8 只萤火虫救援”之外，评估增加一次真实激励广告救援入口。
  - 验收：萤火虫入口不依赖网络；广告入口只有收到完成回调才发放救援，取消或失败不扣资源、不发奖励。
- [ ] 可选增加“结算奖励翻倍”激励广告，并与救援广告错开。
- [ ] 设计插屏广告频率。
  - 建议：前几局不展示；只在结算后展示；设置局数和时间频控。
- [ ] 处理广告未填充、加载超时、离线和 SDK 初始化失败。
  - 验收：任何广告异常都不会阻塞重新开始或返回首页。
- [ ] 审计广告和统计 SDK 的数据收集、跟踪与 Required Reason API。
- [ ] 根据实际 SDK 更新 `PrivacyInfo.xcprivacy`、隐私政策和 App Store 隐私标签。
- [ ] 仅在确实涉及跨 App 跟踪或广告标识符时接入 ATT。
  - 验收：用户拒绝 ATT 后，游戏和非定向广告仍可正常使用。

## P1：数据统计与难度验证

- [ ] 选择正式统计方案和数据保存方式。
- [ ] 验证以下事件真实上报且不会重复：
  - [ ] 首次启动、开始游戏、重新开局。
  - [ ] 每局到达步数、游戏时长、精准落地次数。
  - [ ] 失败所在步数、失败力度偏小或偏大。
  - [ ] 下沉荷叶教程展示与完成。
  - [ ] 萤火虫救援展示、使用、余额不足和救援后继续游玩时长。
  - [ ] 若接入广告，统计广告救援的展示、点击、完成和失败。
  - [ ] 同一会话连续游玩局数。
- [ ] 建立基础数据看板，至少观察：
  - [ ] 首局和前 3 局平均步数。
  - [ ] 10、20、40、70 步到达率。
  - [ ] 失败后的重复开局率。
  - [ ] 萤火虫救援展示率、使用率、余额分布和救援后继续游玩时长。
  - [ ] 次日留存与人均每日局数。
- [ ] 根据数据检查随机生成是否存在不合理组合。
- [ ] 数据稳定前，不继续大规模增加特殊荷叶或复杂养成系统。

## P1：轻量留存候选

以下功能不同时开工，优先选一个做小规模验证：

- [ ] Game Center 好友与全球最高纪录排行榜。
- [ ] 每日固定种子的挑战荷塘，让所有玩家面对同一条路线。
- [ ] 10、20、50、100 步成就。
- [ ] 通过纪录解锁新的荷塘背景或氛围，不恢复皮肤系统。
- [ ] 每日一次免费蜻蜓救援。
- [ ] 可分享的本局成绩卡片。

## P2：App Store 商店资料

- [ ] 确认 App 名称、Bundle Identifier、版本号和 Build 号。
- [ ] 将现有五语言文案录入 App Store Connect。
- [ ] 为简中、繁中、英语、日语、韩语各准备 4～6 张真实游戏截图。
  - 内容建议：单指操作、随机荷塘、下沉荷叶、最高纪录和无尽模式。
- [ ] 确认截图规格、无透明通道且与实际界面一致。
- [ ] 填写主分类、子分类、版权、支持 URL 和隐私政策 URL。
- [ ] 完成年龄分级、内容版权和出口合规问卷。
- [ ] 谨慎决定是否选择 Made for Kids；一旦按儿童类别获批，后续限制更严格。
- [ ] 配置所有目标国家或地区，并逐项处理当地合规提示。
- [ ] 首发使用手动发布，审核通过后再选择正式上线时间。

更细的上架操作见 [`ios/FrogHome/APP_STORE_CHECKLIST.md`](./ios/FrogHome/APP_STORE_CHECKLIST.md)。

## P2：TestFlight 与正式发布

- [ ] 配置签名、证书和 App Store Connect 应用记录。
- [ ] 生成 Release Archive，通过 Xcode Organizer 验证并上传。
- [ ] 先建立内部 TestFlight 测试组。
- [ ] 准备 Beta 描述、测试重点、反馈邮箱和审核联系方式。
- [ ] 建立 10～30 人外部测试组并提交首次 TestFlight Beta Review。
- [ ] 收集设备型号、系统版本、崩溃、截图和文字反馈。
- [ ] 解决 P0 问题后生成新的 Build，并完成回归测试。
- [ ] 填写审核备注，说明离线运行、单指操作、广告触发位置和无账号要求。
- [ ] 提交 App Review，并保存每次审核问题与处理记录。

## 已确定的产品边界

除非后续明确重新讨论，否则不要自行恢复以下设计：

- 核心操作保持为“按住蓄力、松开起跳”，不增加方向控制。
- 当前 H5 是正式开发基线，Cocos 工程仅作对照和备份。
- 不恢复青蛙皮肤系统。
- 不恢复弹力荷花设计。
- 不绘制跳跃路径引导虚线。
- 不绘制下一片荷叶的黄色选中圈。
- 下沉荷叶保留枯黄、裂纹、逐渐下沉和首次暂停教学。
- 萤火虫是永久资源；每局最多消耗 8 只进行一次救援，真实激励广告只能作为额外备选入口。
- 设置面板保留音效、触感开关和重新查看教程入口。
- 荷叶布局强调随机范围，不采用严格重复的十步距离模板。
- 鱼虾只随时间连续游动，不能因青蛙落地或步数变化而瞬移。
- 手机试玩始终使用固定链接：<https://viz323.github.io/frog-home-playtest/>。
